Agent-facing implementation specification
Purpose - This document is the build contract for the repository. It defines the dataset boundary, canonical CNN architecture, 
minimal module structure, training procedure, output artifacts, and acceptance criteria. The coding agent should implement 
this specification directly rather than inventing alternate architectures or infrastructure.
Decision Locked V1 choice
Task 2D binary classification: Non-Stone (0) vs Stone (1)
Dataset Mendeley V2 axial CT JPG dataset; 201 patients
Input 384×384×1 grayscale
Model One canonical custom CNN: 64→128→256→512 channels, 2 
convs/block
Head GAP → Dense192 ReLU → Dropout0.35 → Dense2 Softmax
Training AdamW, LR 3e-4, weight decay 1e-4, batch 16, max 60 epochs
Validation Fixed 5-fold patient-wise CV inside 161 development patients
Final test 40 patients, original images only, opened once after lock
Primary metric OOF ROC-AUC; report sensitivity, specificity, precision, F1, PR-
AUC, confusion matrix
Revision intent: replaces the previous 17-page plan with one canonical implementation path. It removes the CNN-S/CNN-M fork, removes 
conflicting Sigmoid/BCE instructions, reduces configuration and source-file count, and moves 512px / supplied-augmentation experiments out of 
the required V1 build.

1. Scope and non-negotiable decisions
The repository should be small enough to understand in one sitting, but structured so that data logic, model logic, training, and 
evaluation can change independently. V1 is an image-classification research pipeline, not an MLOps platform and not a 
deployment product.
Critical data interpretation - Treat the resource as 201 patients with related source-image families, not as 35,457 
independent observations. The previous plan reports 3,364 original images (1,577 Stone; 1,787 Non-Stone) and a 35,457-
image supplied derivative set.
V1 MUST implement
 Patient-wise outer split: exactly 161 development patients and 40 final-test patients, frozen once.
 Five fixed patient-wise CV folds inside the 161-patient development pool.
 Original images only for every validation fold and for the final test set.
 One canonical 384×384 grayscale CNN with Dense(2) + Softmax output.
 Mild online augmentation only on training images.
 OOF prediction aggregation, OOF-derived decision threshold, explicit candidate lock, then one final-test evaluation.
 Filesystem-based run artifacts with enough provenance to reproduce a result.
V1 MUST NOT implement
 Random image-level train/test splitting.
 Supplied augmented derivatives in validation or final test.
 A second model family, transfer-learning branch, segmentation model, or broad hyperparameter sweep.
 MLflow, Weights & Biases, a database, distributed scheduler, Docker/Kubernetes, or multi-GPU orchestration.
 DICOM or Hounsfield-unit windowing logic: the supplied archive is JPG, so do not invent unavailable signal.
 Any threshold, epoch, architecture, augmentation, or optimizer choice based on the final 40-patient test set.

2. End-to-end pipeline
1.  Prepare the dataset: parse filenames, build a manifest, verify decodability/dimensions, hash files, and identify patient_id + 
source_image_id + label + augmentation status.
2.  Freeze the outer patient split: 161 development patients / 40 sealed test patients. Persist IDs; never regenerate silently.
3.  Freeze five patient-wise folds inside development. Every original/derivative from the same patient inherits the same outer split 
and fold.
4.  Run a smoke test on a small subset to prove decoding, tensor shapes, model forward pass, checkpointing, and artifact 
writing.
5.  Run 5-fold CV at 384×384. Train on original development images plus mild online augmentation; validate on original images 
only.
6.  Reload each fold best checkpoint and save class-1 Stone probabilities for its held-out fold. Concatenate all held-out 
predictions into one OOF file.
7.  Compute OOF metrics and choose the operating threshold from OOF probabilities only. Default threshold rule: maximize 
Youden J.
8.  Explicitly lock the resolved config, threshold, and final epoch budget. Final epoch budget = rounded median of the five best 
CV epochs.
9.  Retrain from scratch on all 161 development patients for the locked epoch budget; do not use the final test for early stopping.
10.  Evaluate once on the sealed 40-patient original-only test set, save raw probabilities/metrics/plots, and export the final model 
bundle.
Hard rule - The final test is a measurement, not a development resource. If the final test looks poor, report it. Do not reopen 
tuning and then present the same test as unbiased.

4.2 Integrity checks before any fit()
 100% parser coverage for files that may enter training/evaluation.
 Every file decodes as expected; corrupt/unreadable files block the run rather than being silently skipped.
 Labels are exactly {0,1}; originals and supplied derivatives are distinguishable.
 No patient appears in more than one outer partition.
 No source_image_id crosses a held-out boundary.
 No exact SHA-256 duplicate crosses a held-out boundary.
 Outer split contains exactly 161 development and 40 test patient IDs.
4.3 Split generation
Generate the patient assignments exactly once. Use group-aware splitting, then audit the resulting image-level class proportions 
and site composition. If the first deterministic split is pathologically imbalanced, fix the split-generation logic once before training 
and freeze the accepted CSVs. After the CSVs are committed, training only loads them.

No silent regeneration - If a split file exists, the code must load and validate it. It must not generate a new split because a 
seed changed, a machine changed, or a user reran the command.
5. Input pipeline and augmentation
5.1 Canonical preprocessing
1.  Read JPG bytes with TensorFlow and decode deterministically as one grayscale channel.
2.  Convert to float32.
3.  Resize while preserving aspect ratio and pad to 384×384 using tf.image.resize_with_pad(..., antialias=True).
4.  Scale pixel values to [0,1].
5.  Return tensor shape (384,384,1) and integer label 0/1.
The exact same decode/resize/scale function is used by training, validation, final evaluation, and exported inference. 
Augmentation is a separate training-only function layered after canonical preprocessing.

5.2 Mild online augmentation - V1 defaults
Transform V1 limit Reason
Rotation ±10° Small acquisition/orientation variation without 
teaching extreme anatomy invariance.
Translation ±3% height/width Small positioning robustness.
Zoom ±5% Small scale variation.
Contrast ±10% Modest intensity robustness for JPG data.
Flips Disabled Do not assume left-right or superior-inferior 
symmetry in V1.
Elastic / perspective / piecewise affine Disabled Too aggressive for the baseline; only later 
controlled experiments may justify them.
Default corpus for V1 training: original images belonging to the current training patients. The supplied 35,457 derivative set is 
indexed but excluded. This avoids conflating more files with more independent patients.
5.3 tf.data order
TRAIN: manifest filter → shuffle(seed) → decode/preprocess → augment → batch → prefetch(AUTOTUNE)
VAL:   manifest filter → decode/preprocess → batch → prefetch(AUTOTUNE)
TEST:  manifest filter → decode/preprocess → batch → prefetch(AUTOTUNE)
Use parallel map with AUTOTUNE. Dataset cache() is optional and should be enabled only if the actual lab machine benefits; 
caching must not change dataset semantics.
6. Canonical model architecture
There is one architecture in V1. In code, name it kidney_cnn_v1. Every Conv2D uses a 3×3 kernel, stride 1, same padding, 
use_bias=False, and He-normal initialization. Each convolution is followed by BatchNormalization and ReLU. Each block ends 
with 2×2 max pooling.

7.1 Fold training sequence
1.  Build train and validation manifests from frozen patient assignments.
2.  Create fresh model weights for the fold. Never warm-start one fold from another.
3.  Compile with AdamW + SparseCategoricalCrossentropy + SparseCategoricalAccuracy. Keep compile-time metrics minimal.
4.  Fit with ModelCheckpoint(best.keras), EarlyStopping(val_loss, patience=8), and ReduceLROnPlateau(val_loss, patience=3, 
factor=0.5, min_lr=1e-6).
5.  After training, reload best.keras regardless of the last epoch.
6.  Predict all original validation images and save path, patient_id, source_image_id, y_true, stone_probability, 
predicted_class_at_0_5.
7.  Save history.csv and best_epoch in fold metadata.

7.2 Why validation loss is the callback monitor
This keeps the training code simple and avoids a custom stateful AUC metric for two-output Softmax. ROC-AUC remains the 
development selection metric, but it is computed reliably offline from saved probabilities produced by each best checkpoint. 
Callback monitoring and research evaluation are deliberately separate concerns.
8. OOF evaluation, threshold, and finalization
8.1 OOF aggregation
After all five folds complete, concatenate the five validation-prediction files. Every development image now has exactly one 
prediction from a model that did not train on its patient. This is the OOF dataset used for model assessment and threshold 
selection.
Metric Definition / use
ROC-AUC Primary threshold-independent ranking metric.
PR-AUC Complementary ranking metric, useful if prevalence changes.
Sensitivity / Recall TP / (TP + FN).
Specificity TN / (TN + FP).
Precision TP / (TP + FP).
F1 Harmonic mean of precision and recall.
Balanced accuracy (Sensitivity + Specificity) / 2.
Confusion matrix TN, FP, FN, TP at the locked operating threshold.
8.2 Threshold rule
Use Stone probability y_pred[:,1]. Calculate the ROC curve from the pooled OOF predictions and select the threshold that 
maximizes:
Youden J = sensitivity + specificity - 1
Save the selected threshold and the OOF metrics that produced it. A 0.5 threshold may be reported as a reference but is not the 
locked operating threshold unless it happens to be selected.
8.3 Final epoch budget and final train
 Collect the best epoch from each CV fold.
 Compute final_epochs = round(median(best_epochs)).
 Write locked_config.yaml containing the resolved configuration, threshold, and final_epochs.
 Create a new model from scratch and train on all original development images (all 161 patients) using the same online 
augmentation for exactly final_epochs.
 No final-test data enters fit(), callbacks, threshold selection, or epoch selection.
8.4 Sealed final evaluation
Run predict() once on original images from the 40 final-test patients. Compute all metrics from the saved raw probabilities using 
the already locked threshold. Save test_predictions.csv before any aggregate metric so all reported results can be regenerated 
later.

11.1 Minimal tests
 Split integrity: synthetic groups prove no patient/source/hash leakage.
 Model contract: random input (2,384,384,1) returns shape (2,2); every row is finite, in [0,1], and sums to ~1.
 Metric correctness: toy y_true/probabilities produce known confusion-matrix counts and specificity/sensitivity.
 Checkpoint round-trip: a tiny synthetic fit saves best.keras; reloaded model produces valid probabilities.
Do not build a large testing framework. These tests protect the high-risk boundaries: leakage, output semantics, metrics, and 
serialization.
12. Definition of done
Repository is complete only when - All acceptance criteria below pass on the real dataset and a clean clone.
 The dataset manifest is reproducible and every used file is decodable and traceable to patient/source IDs.
 The committed outer split contains 161 development and 40 test patients with zero patient/source/hash overlap.
 The five development folds are frozen and reused by every run.
 Validation/test contain original images only; V1 training does not use the supplied 35k derivatives.
 The model is exactly Dense2 Softmax with integer labels and SparseCategoricalCrossentropy.
 All five CV folds train independently and reload their best val_loss checkpoints.
 OOF predictions cover the full development pool exactly once and are the sole basis for the locked threshold.
 Final epoch budget is derived from CV; the test set does not influence training duration.
 The final 40-patient test is evaluated once after an explicit finalize/lock action.
 Raw test probabilities, threshold, metrics, confusion matrix, ROC/PR curves, config, split hashes, dataset hash, Git state, 
and model bundle are saved.
 README documents only the commands required to prepare, smoke-test, run CV, and finalize.
12.1 Deferred experiments - not part of V1 implementation
Only after the canonical pipeline is complete and leakage-free should the project consider these experiments. They must reuse 
the exact frozen split/folds and change one variable at a time.
 512×512 input resolution if both training and validation indicate underfitting or loss of small-detail signal.
 Supplied 35,457 derivative images as training-only data, while keeping validation/test original-only.
 Regularization changes (dropout / weight decay) only if a clear train-vs-CV generalization gap exists.
 A pretrained benchmark only as a comparison, not as a replacement for the custom V1 baseline.
